# 📱 Шаг 6: Мобильная студия съёмки (`mobile.html`)

> **Статус**: ⚪ Запланирован  
> **Цель**: Максимально быстрый и надежный процесс фотосъёмки книг на смартфон с пошаговой разметкой ролей, защитой от сбоев и мгновенной раскладкой по слотам на Mac.

---

## 🎯 Согласованные технические правила

1. **Гибридный сценарий съёмки**:
   - Основной поток: быстрая съёмка в родную камеру телефона $\to$ выбор пачки из галереи.
   - Оперативный досъём: встроенная кнопка `📷 Камера` для мгновенной фиксации забытого ракурса (дефект, выходные данные) прямо в открытую книгу.

2. **Накопительный покнижный цикл**:
   - Оператор добавляет фото Книги #1 $\to$ нажимает кнопку `«+ След. книга»` $\to$ снимает Книгу #2 $\to$ в конце нажимает общую кнопку `«🚀 Отправить пачку на Mac»`.
   - Поддержка переноса ошибочных кадров: долгое нажатие (long-press) на миниатюру фото позволяет перетащить (drag-and-drop) кадр из блока одной книги в блок другой книги прямо на телефоне.

3. **Обязательная экспресс-разметка ролей крупным планом**:
   - Перед отправкой пачки на Mac для каждого кадра открывается режим быстрого крупного просмотра с 5 крупными кнопками в 1 тап:
     - 📕 **«Лицевая обложка»** (`cover_front`)
     - 📘 **«Задник»** (`cover_back`)
     - 📄 **«Титул / Мантра»** (`info_pages`)
     - 🔍 **«Дефект»** (`mantra_defects`)
     - 🎨 **«Иллюстрация»** (`illustrations`)
   - При тапе по роли кадр получает метку и интерфейс мгновенно переходит к следующему снимку.
   - На Mac все фотографии прилетают **уже с готовыми ролями** и автоматически падают в целевые слоты книги без необходимости ручной сортировки мышкой.

4. **Защита от потери данных (Offline-first / IndexedDB)**:
   - Все добавленные фото и состояние сессии автоматически сохраняются в локальное хранилище браузера `IndexedDB`.
   - При входящем звонке, сворачивании приложения или выгрузке вкладки Safari/Chrome ни один снимок не теряется: при повторном открытии страницы вся пачка восстанавливается.
   - Очистка `IndexedDB` происходит только после подтверждения успешной отправки на Mac.

5. **Оптимизация и передача**:
   - Сжатие на клиенте через `createImageBitmap` / canvas до 1600px (качество JPEG 0.82, вес ~250–350 КБ).
   - Порционная отправка по 2 фото за один HTTP POST с автоповтором (до 3 попыток при нестабильном Wi-Fi/LTE).
   - Тактильный вибро-отклик при успешном приеме на Mac.
